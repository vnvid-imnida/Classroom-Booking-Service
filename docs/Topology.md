Исходя из вашей архитектуры (Frontend → Services → Infrastructure + External) и использования **Kafka** в качестве Message Broker, вот рекомендуемое распределение портов.

## Принципы назначения
- **Внутренние сервисы** — слушают на `localhost` или внутри Docker/K8s сети, не торчат наружу.
- **API Gateway / Frontend** — общается с сервисами через внутренние порты.
- **Kafka** — стандартный порт 9092 (внутри), может быть 9093 для SSL.
- **Redis** — 6379.
- **PostgreSQL** — 5432.

---

## 1. Сервисы (Room, Schedule, Booking, Notification, Auth)

| Сервис | Внутренний порт | Назначение |
|--------|----------------|-------------|
| **Room Management** | `8081` | REST/gRPC API для управления комнатами, их характеристиками, статусом обслуживания |
| **Schedule Service** | `8082` | Работа с расписанием (RUZ sync), чтение/запись schedule_cache |
| **Booking Service** | `8083` | Создание/обновление/отмена бронирований, проверка конфликтов |
| **Notification Service** | `8084` | Отправка уведомлений (Telegram, email, WS), чтение из Kafka |
| **Auth Service** | `8085` | JWT-валидация, роли (user/admin), аутентификация |

> Все эти порты доступны **только внутри сети** (Docker network / Kubernetes cluster).  
> На внешний мир смотрит только API Gateway (например, `3000`) или сам Frontend.

---

## 2. Брокер сообщений — Kafka

| Компонент | Порт | Примечание |
|-----------|------|-------------|
| **Kafka Broker** | `9092` | Plain text (внутренний) |
| **Kafka Broker (SSL)** | `9093` | Для шифрованного соединения |
| **Kafka Exporter (Prometheus)** | `9308` | Мониторинг |
| **Kafka UI / Kowl** | `8080` | Веб-интерфейс (опционально, только для дев/админ) |

Все сервисы подключаются к Kafka по адресу `kafka:9092` внутри сети.

---

## 3. Инфраструктура

| Сервис | Порт | Назначение |
|--------|------|-------------|
| **PostgreSQL** | `5432` | Основная БД (все таблицы) |
| **Redis** | `6379` | Кеш (например, schedule_cache дублируется или сессии), pub/sub при необходимости |

---

## 4. Внешние системы (клиенты для сервисов)

| Система | Порт (куда стучатся сервисы) | Кто вызывает |
|---------|-------------------------------|----------------|
| **RUZ API** | `443` (HTTPS) | Schedule Service — забирает расписание |
| **Telegram Bot API** | `443` (HTTPS) | Notification Service — отправка сообщений |

---

## 5. Пример взаимодействия (с портами)

```
Frontend (порт 3000) 
  → API Gateway / обратный прокси (порт 8000)
    → Booking Service (8083)
    → Room Service (8081)
    → Schedule Service (8082)

Booking Service (8083)
  → Kafka (9092) — продюсит booking.created
  → PostgreSQL (5432)
  → Redis (6379) — для блокировок при двойном бронировании

Notification Service (8084)
  ← Kafka (9092) — консьюмит все события
  → Telegram API (443)
```

---

## 6. Docker Compose фрагмент (для ясности)

```yaml
services:
  postgres:
    ports:
      - "5432:5432"   # только для дев-среды, в проде убрать

  redis:
    ports:
      - "6379:6379"

  kafka:
    ports:
      - "9092:9092"
    environment:
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://kafka:9092

  room-service:
    ports:
      - "8081:8081"   # внутренний
    depends_on:
      - postgres
      - kafka

  notification-service:
    ports:
      - "8084:8084"
    depends_on:
      - kafka
```

---

## 7. Особенности для Kafka

- Все сервисы, которые **создают** события (Booking, Schedule, Room), являются **продюсерами**.
- Notification, Audit (если добавите), возможно Schedule — **консьюмеры**.
- Рекомендуется использовать **один порт 9092** внутри сети, без лишней маршрутизации наружу.

Если хотите вынести Kafka UI на внешний порт для наблюдения — используйте `8080` или `9000`.
